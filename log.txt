WHAT WAS BUILT
1. A React + Vite + TypeScript application with Tailwind, Radix/shadcn-style owned UI, React Flow, Zustand, and Lucide.
2. A simple to-do list as the backbone: create, edit, complete, filter, delete, and undo. The same tasks appear on a freely arranged connected canvas. Connections are visual, not enforced dependencies.
3. A looping local MP4 background, glass surfaces, serif headings, readable body text, responsive layout, video pause control, and reduced-motion support.
4. Browser-local persistence and migration of older workspaces.
5. Timezone clock and task start/end times, timestamp-based progress, reminders, and synthesized completion/deadline audio. Deadline alarms loop until dismissed, muted, or resolved.
6. Daily history snapshots and statistics: completion rate, completed/unfinished counts, timed-task averages, statuses, and seven-day trends.
7. Context transitions, stable glass blur, sparkle cursor, report control alignment, larger crosshair connection dots, and saved connection ports.
8. Smart Arrange, run only by its button: timed cards first by start instant, then untimed cards by creation. It adds missing sequential connections while preserving manual/hidden connections and uses measured card heights for spacing.
9. A sticky-note board with click-to-edit notes, selected-text formatting, colours/fonts, checklists, image previews, and document attachments. Autosave uses the shared store.
10. Task attachment controls beneath descriptions. Blobs use IndexedDB, metadata uses localStorage, uploads are limited to 20 MB per file, and errors are shown. Nothing is uploaded to Firebase Storage.
11. A translucent white cursor glow for clickable controls, without intercepting pointer events or text editing.
12. Replaced public/videos/background.mp4 with the creator's newer Flow file Woman_turning_book_page_20261022184732.mp4 (3,348,510 bytes).
13. Updated README and the locally generated Firebase workflows. Workflows use Node 22, npm ci, tests, production build, and Firebase Hosting deploy. Credentials remain in GitHub secrets. Local agent tooling is excluded from application commits.

INITIAL IMPLEMENTATION PROMPT (pasted by the user; full text)
----------------------------------------------------------------
Build a complete, polished, single-page to-do web application called **Taskspace**.

The product is a simple task manager with two views: a familiar list and a freeform canvas where users can arrange task cards and connect them with lines. Basic task management is the backbone. The canvas is an alternate view of the same tasks.

Implement the working application, including persistence, responsive styling, and all interactions described below.

## 1. Technology

Use:

- React + Vite + TypeScript
- Tailwind CSS
- shadcn/ui for accessible dialogs, dropdowns, tooltips, and related controls
- React Flow (`@xyflow/react`) for the canvas
- Zustand for shared application state
- localStorage for persistence
- Lucide React for icons

Use compatible stable package versions. Inspect an existing project before changing its setup. Keep the implementation modular and straightforward.

Do not add authentication, a backend, Gemini integration, project management, or a separate marketing website.

## 2. Product scope

Create one task workspace with:

- Add tasks.
- Edit task titles and optional descriptions.
- Complete tasks and reopen completed tasks.
- Delete tasks with an Undo action.
- Filter by All, Active, and Completed.
- Display a compact completion count.
- Switch between List and Canvas views.
- Freely drag and position task cards in Canvas view.
- Connect cards with lines.
- Select and remove connections.
- Pan, zoom, and fit the canvas to its contents.
- Automatically save tasks, connections, card positions, and view preferences.

Connections are purely visual. Users decide whether a connection represents an order, an association, or something else.

Do not enforce prerequisites, block task completion, detect dependency cycles, or automatically rearrange the user’s cards.

## 3. Visual direction

The aesthetic is cinematic, minimal, calm, and premium.

Use the specifications below as the complete visual direction. No external reference website is needed.

Combine:

- A fullscreen atmospheric video background.
- Deep navy tones.
- Elegant Instrument Serif display typography.
- Inter for functional interface text.
- Restrained liquid-glass controls.
- Dark translucent task surfaces.
- Generous spacing and subtle motion.

Avoid decorative blobs, radial gradients, neon glows, large dashboard panels, excessive badges, and generic productivity-dashboard styling.

This is a usable task page. Keep its heading compact enough that the quick-add input and tasks remain visible without scrolling on a typical laptop.

## 4. Local background video

I already have my own background video stored locally on my computer. Use that video as a project asset instead of downloading a video or using an external media link.

Asset setup:

- The intended project location is `public/videos/background.mp4`.
- First check whether that file already exists in the project.
- If I provide a local source path, copy the video into that project location, leaving the original unchanged. Do not overwrite a different existing video without asking.
- If the video is missing and I have not provided its location, ask me for its exact local path or ask me to place it at `public/videos/background.mp4`. Continue building the rest of the app with the navy fallback while waiting.
- Do not search unrelated folders on my computer for the video.
- Do not use Google Drive sharing links, remote video URLs, or a Windows filesystem path as the HTML video source.

Serve the video through Vite. For a root deployment, its browser URL is `/videos/background.mp4`. For compatibility with a configured deployment base path, derive the source as:

const backgroundVideoSrc = `${import.meta.env.BASE_URL}videos/background.mp4`;

The `public` folder name must not appear in the browser URL. Vite copies this asset into the production build, so it deploys with the site.

Create a fullscreen background video with:

- loop
- muted
- playsInline
- preload="metadata"
- aria-hidden="true"
- object-fit: cover
- pointer-events: none
- A source element using backgroundVideoSrc and type="video/mp4"

Autoplay when motion preferences allow it. Check prefers-reduced-motion before starting playback so users requesting reduced motion do not briefly see autoplay. Handle rejected play() promises gracefully.

Position the video in a fixed full-screen container behind the application. Keep content above it with explicit stacking layers. The background must not intercept clicks or scroll independently.

Do not add a full-page tint overlay or decorative gradient over the video. Make controls and task cards readable through their own surface backgrounds.

Use the deep navy background color while the video loads or if the file is missing, unsupported, or fails to play. The task application must remain fully usable even if the video fails.

Provide a small accessible pause/play control whose label reflects actual playback state. Respect explicit user choices and do not restart the video when tasks change or when switching between List and Canvas. Disable nonessential entrance animations for reduced motion.

Use the supplied local video as-is. If its file size noticeably slows loading, report that and suggest compression without silently replacing or modifying the original.

## 9. Canvas view

Use React Flow with custom task nodes.

### Task cards

Each node includes:

- Completion checkbox.
- Task title.
- Optional short description.
- Edit/delete menu.
- Connection handles.
- A clear drag area.

Use the same visual language as List view.

Checkboxes, menus, and other interactive elements must not start a drag or pan action. Apply React Flow’s appropriate interaction classes.

### Free arrangement

Users can drag cards anywhere.

- Save coordinates at the end of a drag.
- Preserve manually arranged positions.
- Do not automatically run a layout algorithm.
- Give new cards deterministic, non-overlapping initial positions.
- When adding a task from Canvas view, place it near the visible canvas area.
- Persist and restore the viewport.

### Connections

Users drag between handles to connect cards.

- Use thin, understated, clearly visible lines.
- Start with neutral lines without arrowheads.
- Lines follow cards as they move.
- Allow connections among any distinct tasks, including completed tasks.
- Reject self-connections.
- Reject duplicate connections, including reversed duplicates for these undirected visual lines.
- Allow cycles involving multiple tasks.
- Let users select a connection and remove it with a visible action.
- Support Delete/Backspace for selected edges only when focus is not in an input or editable element.
- Do not interpret lines as enforced dependencies.

Use a larger invisible interaction area around thin lines to make selection easier.

### Navigation and filtering

Include:

- Zoom in.
- Zoom out.
- Fit view.
- Pan interaction.
- A concise hint: “Drag cards to arrange. Drag between dots to connect.”

Keep React Flow controls visually consistent with the app.

Use a transparent canvas background or a very restrained surface. If a dot grid is necessary for orientation, keep it extremely subtle.

When filtering tasks:

- Hide filtered-out cards.
- Hide lines unless both endpoint cards are visible.
- Preserve all hidden cards, positions, and connections in storage.
- Show a clear empty state if the filter matches no tasks.

Do not persist filtered React Flow nodes as the full underlying task collection.

## 10. State and persistence

Use one shared store as the source of truth.

Suggested types:

type Task = {
  id: string;
  title: string;
  description: string;
  completed: boolean;
  createdAt: string;
  updatedAt: string;
};

type TaskPosition = {
  x: number;
  y: number;
};

type TaskConnection = {
  id: string;
  sourceTaskId: string;
  targetTaskId: string;
};

type Preferences = {
  view: 'list' | 'canvas';
  filter: 'all' | 'active' | 'completed';
  viewport: {
    x: number;
    y: number;
    zoom: number;
  };
};

Store:

- Tasks.
- Task positions keyed by task ID.
- Connections.
- Preferences.
- A persisted schema version.

Derive React Flow nodes and edges from this store. Avoid maintaining independent copies of task content in each view.

Use crypto.randomUUID() or an equivalent reliable ID mechanism.

Persist under a clearly named localStorage key.

Handle:

- Missing storage.
- Invalid JSON.
- Invalid stored fields.
- Unsupported schema versions.
- Storage write failures.
- Orphan connections referencing missing tasks.

If saving fails, keep the app usable and show a concise message that changes could not be saved.

Include a discreet note such as “Saved in this browser” so users understand the storage scope.

Do not seed fake tasks into the user’s saved data by default.

## 11. Delete and undo

Deleting a task should:

1. Remove the task.
2. Remove its saved position.
3. Remove its incident connections.
4. Show a toast with an Undo action.

Undo should restore the task, its original list position, saved canvas position, and connections whose other endpoints still exist.

Keep a bounded undo snapshot for the most recent deletion. Make rapid consecutive deletions behave predictably. Ensure toast expiration and stale actions cannot restore the wrong task.

IMPLEMENTATION CHOICES
- The auto graph action is named Smart Arrange. Mixed scheduled/unscheduled lists put timed tasks first, then untimed tasks. Identical creation timestamps retain list order.
- Existing manual lines are preserved rather than silently erased. Smart Arrange may add missing sequence lines; clicking again does not create duplicates. A filter limits arrangement to visible tasks.
- Rich text is saved through an allowed-format sanitizer; paste inserts plain text. Attached image files are rendered from local Blob URLs separately.
- File contents use IndexedDB to avoid exhausting localStorage with base64 documents. Firebase Hosting remains hosting, with no account/database/storage backend added.
- README tool credits reflect the creator's confirmation. This app has no runtime Gemini API integration; no AI feature or external tool prompt history is claimed without evidence.
